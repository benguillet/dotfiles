# Test Apply Locally

Run the full Apply path in Ben's Work Chrome. Diagnose environment failures before changing product code.

## 1. Confirm the workspace

Run:

```zsh
ycli --help
git status --short --branch
git rev-parse HEAD
git branch --show-current
yc config get conductor_remote
yc stacks url
```

- Read the nearest repo instructions and the `agent-frontend`, `agent-backend`, and `rc` skills when their scopes apply.
- If `CONDUCTOR_IS_LOCAL=0`, read the repo `cloud-env` skill before app, test, database, MR, or pipeline work.
- If `conductor_remote` is true, follow Ben's remote-devbox rules. Keep Git and light inspection local.
- A branch can be checked out in another worktree. A detached checkout of the exact remote commit is valid for local testing; verify the SHA instead of moving another worktree's branch.
- Record the initial Git status. Never remove pre-existing changes.

## 2. Start only the required apps

Run:

```zsh
yc start apply,bookface,ycinternal
```

Do not restart a healthy stack. Use `yc stacks url` for the actual local hosts; do not assume a stack name, port, or protocol.

Open Apply at its local `/home` URL.

## 4. Repair database readiness only when logs prove it

If Apply `/home` shows `ApiClient::ApiClient::InternalServerError`, inspect Rails logs:

```zsh
yc logs --tail 800 --no-follow --source rails
```

Do not pipe a `yc` command. For a large log, redirect it and inspect it after the command completes:

```zsh
yc logs --tail 4000 --no-follow > /tmp/apply-local.log 2>&1
rg -n -C 12 'PendingMigrationError|BfAgentsChatResponseJob|BfAgent .*error|ChatChannel#heartbeat' /tmp/apply-local.log
```

If ycinternal reports pending migrations, run:

```zsh
yc db migrate
```

`yc db migrate` can update generated model annotations. Compare with the initial Git status and restore only files generated by this command that are unrelated to the branch. Never discard user changes.

For a confirmed empty or rebuilt development database, run:

```zsh
YC_NO_DAEMON=1 yc db seed
YC_NO_DAEMON=1 yc ssh ycinternal development -c 'bundle exec rake db:sync_permissions'
```

Do not seed or reset a working database. If PostgreSQL reports a broken `pg_wal` symlink, treat it as local database corruption. Use the normal database recovery path first. Patch and rebuild the database image only when its logs prove that exact problem, and revert any temporary source patch immediately.

## 5. Give the local user chat access

Account can create `benguillet` with no roles. After the first sign-in, inspect the one local row with the repo `rc` helper:

```zsh
.claude/skills/rc/rc-run -a internal -e dev 'u = User.find_by!(hnid: "benguillet"); puts({id: u.id, roles: u.roles, has_messages_access: u.has_messages_access?, agent_chat_enabled: u.agent_chat_enabled?, temporarily_banned: u.temporarily_banned_from_messages?}.inspect)'
```

If both access values are false, state that the next command changes one development row, then use this local-only fallback:

```zsh
.claude/skills/rc/rc-run -a internal -e dev 'u = User.find_by!(hnid: "benguillet"); u.update_columns(roles: (u.roles + [YC::Roles[:yc_staff]]).uniq, updated_at: Time.current); u = User.find(u.id); puts({roles: u.roles, has_messages_access: u.has_messages_access?, agent_chat_enabled: u.agent_chat_enabled?}.inspect)'
```

Use `update_columns` here because unrelated user callbacks can reject and roll back a normal `update!` on sparse seed data. Never run this command in production. Reload Apply after the update.

## 6. Verify batch seed integrity before agent generation

The YC Agent system prompt requires a previous, current, and next batch. Check them before sending a message:

```zsh
.claude/skills/rc/rc-run -a bookface -e dev 'puts({previous: Batch.previous&.name, current: Batch.current&.name, next: Batch.next&.name}.inspect)'
```

If one is nil, inspect the local sequence:

```zsh
.claude/skills/rc/rc-run -a bookface -e dev 'puts Batch.unscoped.order(:position).pluck(:id, :name, :current, :position).last(20).inspect'
```

Repair only the proven missing or stale local rows. As of August 2026, the standard seed can omit `p2026` and still mark `w2026` current. This causes:

```text
NoMethodError: undefined method 'name' for nil
BfAgents::SystemPrompt::RuntimeContext.batch_context_lines
```

For that exact state, mark `s2026` current, insert `p2026`, and place it between Winter and Summer. The `position` column has a unique index, so move later rows through a temporary offset inside one transaction:

```zsh
.claude/skills/rc/rc-run -a bookface -e dev '
Batch.where(current: true).update_all(current: false, updated_at: Time.current)
Batch.find_by!(name: "s2026").update_columns(current: true, updated_at: Time.current)
unless Batch.exists?(name: "p2026")
  Batch.transaction do
    Batch.unscoped.where("position >= ?", 46).update_all("position = position + 1000")
    Batch.unscoped.where("position >= ?", 1046).update_all("position = position - 999")
    Batch.create!(name: "p2026", type: :core, position: 46)
  end
end
Batch.invalidate_batch_caches!
puts({previous: Batch.previous&.name, current: Batch.current&.name, next: Batch.next&.name}.inspect)
'
```

Do not use this dated repair when the rows differ. Derive the correct previous and next batch from `YC::Timeline` and the active application batch.

## 8. Know the expected messaging path

The Apply bundle embeds `@yc/messages`; it does not embed the Bookface UI. The client calls the existing Bookface Messages host with credentials:

1. `GET /messages/application_shell.json`
2. `GET /messages/agent_prompts_fast?count=2&referrer=apply`
3. `POST /messages` for the first message and chat creation
4. `GET` or `POST /messages/:id/chat_messages` for existing chats
5. `POST /media` and `POST /media/:id/upload_complete` for uploads
6. `POST /verify-session` for CSRF/session refresh
7. Existing `ChatChannel` over ActionCable for live updates

Bookface CORS must allow the exact Apply origin with credentials. ActionCable must allow that origin only on the Messages host and only for `ChatChannel`.

## 9. Diagnose agent response failures in the correct process

Local Bookface commonly uses Active Job `Async`, so `BfAgentsChatResponseJob` appears in `bookface-rails`, not `bookface-sidekiq`. Search Rails logs first.

- `POST /messages` and one `ChatMessage` create prove HTTP send and persistence.
- `ChatChannel#heartbeat` and `Connected` prove ActionCable.
- `Error generating response` means the message path worked but the agent job failed.
- `RuntimeContext.batch_context_lines` with nil `.name` means batch seed state is incomplete.
- AWS credential or access errors mean renew SSO in Work Chrome and retry.
- An Unleash `sts:AssumeRole` error is not by itself proof that the agent LLM call failed.
